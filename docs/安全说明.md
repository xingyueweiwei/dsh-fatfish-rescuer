# 🛡 安全说明 —— 大肥鱼救星会动什么、怎么回滚

> 给别人用之前，这一页比"功能列表"更重要。
> **结论先放这儿：它对配置的每一次改动都有三重保护（原子写 → 写后校验 → 失败自动回滚），
> 且改动前会自动打快照。它不联网、不上报。**
>
> **v5.0 补一句最要紧的**：它**不会**去杀"别处的 dsh" ——
> 默认只处理**当前端口上的那个实例**，你另起的（别的端口）它一个都不碰；
> 而且 `--plan-kill` 能把"现在动手会结束哪些进程"先列给你看，**一个都不杀**。
> 详细取证过程见文末「七、v5.0：关于"会不会杀掉别的 DSH"的正面回答」。

---

## 一、三重保护是什么

### ① 原子写（不会写出"半截文件"）

改配置不是"打开原文件直接改"，而是：

```
写入同目录临时文件  →  成功后再整体替换原文件
```

⇒ 即使写到一半断电/被杀，**原文件仍然完好**（坏的是临时文件，且临时文件会被保留下来供取证，不会被静默删掉）。

> 这条规矩来自一次真实事故：曾有脚本直接就地覆写活动配置，导致三个配置文件在同一秒变成碎片、DSH 直接起不来。

### ② 写后校验（写完立刻验，不合格就回滚）

写完立刻检查**结构是否合法**：

- JSON：能否解析、有无尾随逗号、有无两个对象拼接、有无截断片段
- YAML：能否解析、顶层是否序列、有无重复块

**不合法 → 立刻回滚到上一个合法版本**，并报错。

### ③ 改动前快照（可随时回到过去）

每次改动关键配置前，自动把相关文件快照到：

```
%USERPROFILE%\.dsh\big-fat-fish-rescuer\config-snapshots\<时间戳>\
```

- 保留**最近 40 份**（自动轮换，不会无限增长）
- 快照目录里有 `MANIFEST.txt`，写明这次快照包含哪些文件
- 也提供**手动快照**：点 `🛡 备份配置`
- 恢复：点 `♻ 恢复配置`（有确认框）从列表里挑一份

## 二、它到底会碰哪些文件

### 会修改的（全部走上面三重保护）

| 文件 | 什么时候改 | 对应按钮 |
|---|---|---|
| `~/.dsh/profiles/web/cordis.patch.yml` | 修复皮肤互斥 / 禁用崩溃插件 | 💊 / ⛔ |
| `~/.dsh/profiles/web/package.json` | 修复插件登记 | 🩹 |
| `~/.dsh/whale-desktop-launcher/launcher.ini` | 修正启动配置里的端口不一致 | 🩺 / 🚦 |
| `~/Desktop/.../node_modules/@deepseek-ai/dsh-win32-process/lib/index.js` **（DSH 内部文件）** | 打"子进程不弹控制台窗口"补丁 | 🧩 补丁体检 |
| `~/.dsh/profiles/web/node_modules/argo-search/bin/argo.js` **（插件内部文件）** | 打 `windowsHide` 补丁 | 🧩 补丁体检 |
| `~/.dsh/profiles/web/pnpm-workspace.yaml` + `pnpm-lock.yaml` | **v5.0 新增**：给"要构建授权"的插件加 `allowBuilds` | 🔍 研究插件（改前备份这两个文件；改后跑一次 `pnpm install` 复验；不过则回滚配置**并再跑一次 install 还原 node_modules**） |

> ★ **关于改 node_modules**：这两处补丁是**刻意为之**，用来根治"一直弹 PowerShell 黑窗"。
> 它们**会被 DSH / 插件升级覆盖** —— 覆盖后症状复发，点一下 `🧩 补丁体检` 就能重打。
> 不想让程序碰这两个文件？那就**别点「🧩 补丁体检」**，其余功能不受影响。

### 只写自己的目录（不碰你的东西）

```
%USERPROFILE%\.dsh\big-fat-fish-rescuer\
├── config-snapshots/      ← 配置快照（保留 40 份）
├── dsh-web.out.log        ← 启动日志
├── inprivate-<端口>.log   ← 无痕启动的临时日志
├── envcheck-report.txt / configtest-report.txt / selftest-report.txt
├── diagnose-<时间戳>/     ← 导出诊断包（脱敏）
└── run-times.txt          ← 各按钮耗时统计
```

### 注册表：**只碰一个键，且只在你点那个按钮时**

| 键 | 何时改 | 改成什么 |
|---|---|---|
| `HKCU\Console\%%Startup` | **只在点 `🖥 默认终端` 并选择修复时** | 把 `DelegationConsole` / `DelegationTerminal` 设为 **Conhost** 的 GUID |

**为什么**：Windows 允许把"默认终端"设成 Windows Terminal，那样**任何程序新建控制台都会被放大成一个终端窗口** —— 这正是"一直弹黑窗"的第四个来源。改回 Conhost 即可根治。

> 这个键是**用户级**的（`HKCU`，不需要管理员权限），且不影响你手动开终端的行为。
> 想改回去：Windows「设置 → 系统 → 终端 → 默认终端应用程序」自己选即可。

### 系统启动项：**只在你点 `🌅 开机自启` 时**

在「启动」文件夹创建一个快捷方式：

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\大肥鱼救星-自愈.lnk
```

它让救星在登录时**以 `--autorecover` 静默跑一次自检修复**（无窗口、不打扰）。

> ⚠ **注意语义**：`--autorecover` 跑的是**「强力自愈」** —— 会结束 dsh 进程、重启 dsh web、
> 顺带检查本地绘图服务、并打开桌面客户端。也就是**每次登录都会这么做一次**。
> 如果你希望"登录后什么都不动"，请不要启用它。

不想要了：**再点一次 `🌅 开机自启`** —— 现在它会识别出"已经启用"，并询问是否**取消**
（取消只删这个快捷方式，别的一律不动，且会先备份一份 .lnk 到救星目录）。
也可以自己在「启动」文件夹里删掉它。

## 三、它**不会**做的事

| 不会 | 说明 |
|---|---|
| ❌ 不联网、不上报 | 程序内没有任何上报逻辑；诊断包是导出到本地，发给谁由你决定 |
| ❌ 不删你的文件 | 唯一会 `Delete` 的是它**自己**在 `big-fat-fish-rescuer\` 里创建的临时日志 |
| ❌ 不动你的会话/对话记录 | `~/.dsh/sessions/` 只读，不写不删 |
| ❌ 不动你的作品/文档 | 完全不涉及 `Desktop` 下的个人文件 |
| ❌ 不需要管理员权限 | 全部是用户级操作（`HKCU` / 用户目录） |
| ❌ 不会静默重启 DSH | 凡是会**杀进程 / 写配置 / 写注册表 / 写启动项**的按钮**都有确认框**：重启服务、停止服务、关闭界面、**强力自愈**、**一键修复**、修复插件、补丁重打、默认终端、**禁用崩溃插件**、**修复皮肤互斥**、**开机自启** |
| ❌ 不会杀"无辜的程序" | 结束进程前会**校验身份**（命令行必须指向 dsh 的入口 `bin.js`）。端口被别的程序占用时**只提示、不代杀**；读不到命令行时**宁可不杀** |
| ❌ 不会杀"别处的 dsh"（**v5.0 新增**） | 结束范围**默认收窄到当前端口**：只动命令行带 `--port <当前端口>` 的实例，其它端口的 dsh **一个都不碰**（清单里会写明"另有 N 个 dsh 在别的端口上，本次不会碰"）。只有在**按端口一个都没认出来**时才回退全机，并且会在清单与报告里**明确写出"本次是回退成全机范围"** |
| ❌ 不会在没退路时改动配置 | 需要先备份的关键操作，**快照失败就中止**（「恢复配置」尤其如此） |
| ❌ 不会替你换皮肤 | 「修复皮肤互斥」会**保持你当前正在用的皮肤**，不会重置成官方外观 |

## 四、边界：它做不到什么

诚实列出，免得你对它有错误期待：

1. ~~**它不知道你机器的具体情况** —— 诊断文案里有若干处写死了"3080 端口"。~~
   **（v4.2 已修）** 诊断与提示里的端口现在一律取**运行时实际发现的端口**，不再写死 3080。
   不过如果你的 DSH 端口是**手工改过**的，仍建议以顶部状态栏和「🚦 启动链路自检」为准。
2. **ComfyUI 相关功能对你是空转** —— 它内置了"检查并拉起本地绘图服务（ComfyUI :8188）"的逻辑（原作者本机用它生图）。你没装 ComfyUI 时它会报一句 WARN 然后跳过，**不影响其它功能**。
3. **补丁针对特定版本的 node_modules 文件结构** —— 如果 DSH 大版本升级后文件结构变了，补丁可能打不上（会明确报错，不会静默搞坏）。
4. **它不是杀毒/系统修复工具** —— 只处理 DSH 相关的故障。
5. **一次性 token 是 DSH 的设计** —— 它只能"抓"和"复用"认证地址，不能取消这个机制。

## 五、万一出事，怎么回滚

按这个顺序：

1. **看日志区** —— 界面下方文本框写明了每一步做了什么、失败在哪
2. **点 `✅ 配置自检`** —— 它会列出关键配置文件是否合法（若有损坏会直接指出）
3. **点 `📚 快照列表`** → 找到出问题**之前**那份快照 → **点 `♻ 恢复配置`**
4. 还不行 → 点 `📦 导出诊断包`，把目录发给能帮你的人
5. 最坏情况：配置都在 `~/.dsh/profiles/web/` 下，快照里有历史版本，**手工复制回去**即可

## 六、隐私

- 诊断包导出前会**自动脱敏**：你的用户名（含 URL 编码形式）与主目录路径会被替换成 `USER` / `~`
- 但仍然包含：系统版本、CLR 版本、DSH 版本、配置文件内容片段、日志尾部
- ⇒ **发出去之前建议自己扫一眼**，确认没有你不希望外传的内容

## 七、v5.0：关于"会不会杀掉别的 DSH"的正面回答

主人这次的原话是「**最后判断下会不会导致直接或者间接杀了别的 dsh，我真怕了**」。
下面是**逐条查代码 + 两个对照实验**得到的答案，不是安慰话。

### 结论

| 问题 | 回答 |
|---|---|
| 会不会**直接**杀掉另一个 DSH？ | **不会。** 全代码里能结束进程的地方只有 6 处，每一处都只作用于**它自己刚启动的子进程**，或者**通过了身份校验的 dsh 进程**（见下表） |
| 会不会**间接**杀掉另一个 DSH？ | **v5.0 之前：会。** 已经修好了。详见下面 B 条 —— 这是本次最实的一件事 |

### A. 全部"能结束进程"的代码点（逐条查过）

| 位置 | 它杀谁 | 判据 |
|---|---|---|
| `DshCore.StopDsh` / `RestartDsh` / `ForceRecover` | dsh 进程 | ① 进程名必须是 `node`；② 命令行**入口必须指向 dsh 的 `bin.js`**（`IsDshEntry`）；③ **范围＝当前端口**（v5.0）；④ 受 🛡 只诊断约束；⑤ 有确认框 |
| `DshCore` 端口占用者兜底 | 端口占用者 | 同样要求"确认是 dsh"，否则**跳过并写进报告**（"端口被某某程序占着"） |
| `PluginScout`（🔍 研究插件） | **只杀它自己刚起的 `cmd.exe` 及其子树** | PID 取自它自己 `Process.Start` 的返回；超时用 `taskkill /T /F /PID <自己的 pid>` |
| `PatchLock` / `PathAudit` / `Program` 里的几处 `Kill()` | **只杀它自己刚起的子进程** | 同上，PID 都是自己 spawn 的 |

⇒ 没有任何一处"按名字批量杀 node"、"按端口杀一切占用者"的老式写法（那两处历史上确实有过，已改成身份校验版，注释里留着事故记录）。

### B. 那个真的存在过的"间接"路径（已修）

**现象**：身份判据 `IsDshEntry` 是**全机扫描**的，跟端口无关。而"按端口收窄"以前**只在设了
`DSH_PORT` / `BFF_DSH_HOME` 环境变量时才生效** ⇒ **日常使用下，「停止服务 / 重启服务 / 强力自愈 / 一键修复」
会把机器上所有 dsh 实例一起结束** —— 包括你另起的、在另一个端口 / 另一个 profile 上的那个。
（这不是我推测的：那个 agent 的代码注释里就记着一次实测事故——沙箱跑了一次，用户线上正在承载会话的 dsh 随之从进程表消失。）

**v5.0 的修法**：默认就按端口收窄；一个都没认出来才回退全机，并且**必须把回退这件事写出来**
（清单、报告、确认框三处都会显示范围）。四个确认框（停止服务 / 重启服务 / 关闭界面 / 一键修复 / 强力自愈）
现在都会先告诉你：`本次会结束 N 个 dsh 进程（PID …）。只动当前端口 X 的实例；另有 M 个 dsh 在别的端口上，本次一个都不会碰。`

**实测取证（本机 2026-09-20，阳性 + 阴性对照）**：
1. 造一个替身进程：命令行长得像"另一个端口上的 dsh"（`…\@deepseek-ai\dsh\lib\bin.js web --no-open --port 3199`），
   但它其实是 `node -e` 睡 120 秒 —— **绝不会真的起 DSH**；
2. 跑 `--plan-kill`（默认）⇒ 名单里**只有** 3080 那个实例，替身**不在名单**，并明确输出
   "另有 1 个 dsh 在**别的端口**上，本次**一个都不会碰**"；
3. **阴性对照**：把 `DSH_PORT=3199` 设上再跑 ⇒ 替身**出现在名单里**（证明识别逻辑确实看得见它，
   所以第 2 步的"没进名单"是**真的被排除了**，不是判据瞎了）。

### C. 还想更保险？两个开关

- **`大肥鱼救星.exe --plan-kill`** —— 先看名单，**一个都不杀**；
- **🛡 只诊断**（或 `--readonly on`）—— 拉上之后，重启 / 停止 / 一键修复 / 强力自愈 / 插件适配
  **全部被直接拒绝**，救星连进程都不碰。

### D. 唯一还需要你知道的"会改东西"的新动作

「🔍 研究插件」会在**真实 profile** 里跑一次 `pnpm install`（这是它的功能本身，不是副作用）：
它**不会结束、不会重启**任何 dsh，但会按新配置重装一次插件目录。
改前备份 `pnpm-workspace.yaml` + `pnpm-lock.yaml`，复验不通过则回滚配置**并再跑一次 install 还原 node_modules**；
🛡 只诊断开着时它一个字节都不写。
它到底动不动手，有 **13 项机器判据**（`--scout-selftest`，全在临时沙箱 + 假 pnpm 里跑，不联网）每次发版都会验。
