# 🐋 大肥鱼救星 · 症状速查（图文版）

> **怎么用**：先看「你看到的」那一列，再点对应的按钮 —— **不用懂命令行**。
> 本工具所有"会改东西"的动作都**先打快照**，随时能回滚；拿不准的它只报不改。

---

## 一、看到这句报错 → 就点这个（最省事的一条线）

| 你看到的报错 / 现象 | 它在说哪一层 | 点这个 |
|---|---|---|
| `Failed to fetch (gateway/internal)`（页面还开着，一操作就弹） | 浏览器连不上本地服务 | 🌐 **打开无痕**（用**当前**地址重开）；服务没起来就先 🚀 启动并打开 |
| `cannot resolve profile bundle "X"`；或"装完插件就起不来" | 插件清单里有**悬空引用** | 🩺 **装后体检** → 🧹 **清理悬空引用** |
| `duplicate loader entry id: X` | 同一个 id 被**两个 bundle 层各插了一次** | 🩺 → 🚫 **去重重复条目**（升级版：把它转成**顶层 id-patch**，**保住它原来的配置**，而不是删掉） |
| 某个会话**打不开**（重启也进不去那个会话） | 会话文件被写坏（社区把它分成 seq 断档 / zstd 截断 / 孤立代理项等 8 类） | 本工具目前只能做文件级浅体检并**指路**；深度修复请用社区专用工具 [`dsh-session-surgeon`](https://github.com/xiaoshenming/dsh-session-surgeon)（默认 dry-run、先备份、绝不凭空补 seq） |
| `pending (waiting for services: X)` | **等不到服务**（它依赖的插件被禁用了） | 🩺 → ♻ **启用被禁条目** |
| `listen EADDRINUSE ... already in use` | 端口被占（**不是插件坏**，别去禁用它） | 🔧 **一键修复**，或 🚀 启动并打开 |
| `listen EACCES: permission denied 127.0.0.1:3080` | **端口没权限绑**（Windows 上 3080 常落在 Hyper-V/WSL2 的**保留端口区间**里，不是被占用） | **换端口**：把端口号写进 `%USERPROFILE%\.dsh\big-fat-fish-rescuer\port.txt`（例如 3090）或设 `DSH_PORT=3090`；🩺 装后体检里有一节专门帮你查"当前端口是否落在保留区间" |
| `installed package X main entry is missing at Y` | 插件装坏了（包在、入口不在） | 🩺 → 📦 **重装插件** |
| `ERR_PNPM_IGNORED_BUILDS` / `Ignored build scripts: X` | 插件要跑自己的构建脚本，宿主要求先**点名授权**（**不是插件坏**，也别急着禁用它） | 🔍 **研究插件**（在「🧩 插件与皮肤」页）：先给你一份预演，确认后才改配置 |
| `unknown prompt variable`；或"启动直接失败、我起不来" | 记忆文件里写了**字面量花括号** | 🧩 **补丁体检**（第 ④ 项），可一键重打防线 |
| `ENOENT ... assets` | 插件启动时要用的资源缺失 | 🚨 排查崩溃插件 → ⛔ 禁用崩溃插件 |
| 界面错乱 / 美化功能点不动 | 多套皮肤同时生效 | 💊 **修复皮肤互斥** |
| 说不清是谁的问题 | —— | 🧭 **分层判定**（还能选**别人发来的日志**一起判） |

> **一句提醒**：上面这些报错常常长得很像，但**层次完全不同**。
> 拿不准就先点 **🩺 装后体检** —— 它报告的第一屏就是「症状 → 该点哪个」的对照表。

## 三、三条最常用的路

1. **打不开 / 白屏 / 转圈** → 点 🩺 **装后体检**，看第一屏的对照表，按它指的按钮点。
2. **装完插件出毛病** → 同上。若报告判出「悬空引用 / 重复条目 / 等不到服务」，**它旁边就有修复按钮**。
3. **别人求助、把日志发给你** → 点 🧭 **分层判定**，选中他的日志文件 ⇒ 立刻知道这问题出在哪一层。

## 四、它**不会**做的事（可以放心）

- 不删你的插件包、不动 `settings.yaml` 里的密钥；
- 所有修复**先快照**、只改该改的那一行/那一项、写完**立刻校验**，坏就放弃；
- 拿不准**只报不改**（例如"等不到服务"只给候选，要你确认后才启用）；
- **杀进程只杀它认得出是 dsh 的**：端口被别的程序占着时它**绝不**去杀，只会叫你自己处理或换端口；
  v5.0 起范围进一步收窄 —— **默认只动当前端口上的那个 dsh 实例**，你另起的（别的端口）它一个都不碰；
- 怕它乱动就把 **🛡 只诊断**拉上：拉了之后它**绝不结束、绝不启动任何 dsh 进程**。

> ⚠️ **唯一的例外要说清楚**：你手动点「🔍 研究插件」并在确认框里同意之后，
> 它会**备份后**改 `pnpm-workspace.yaml`、并在你的真实 profile 里**跑一次 `pnpm install`**
> ⇒ 插件目录会按新配置重装一次（复验不通过会自动回滚配置并再跑一次 install 还原）。
> 这一步是你要它做的，不是它自己偷偷做的。

## 五、还是不行怎么办

1. 看界面下方的**运行日志区**：每一步做了什么、失败在哪都写在那里；
2. 点 **📦 导出诊断包**（已脱敏：用户名和路径会被替换），把生成的目录发给能帮你看的人；
3. 日志与快照都在：`%USERPROFILE%\.dsh\big-fat-fish-rescuer\`。
