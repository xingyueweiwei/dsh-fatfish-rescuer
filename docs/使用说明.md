# 🐋 大肥鱼救星 · 使用说明（v5.0）

> **一句话**：DSH（DeepSeek Harness）打不开、很慢、一直弹黑窗、界面错乱、配置被改坏时，
> 双击这个 exe，点对应的按钮就行 —— **不用懂命令行，不用找我**。
>
> ▶ **只想按症状点按钮**：先看同目录的 **`症状速查（图文）.md`**（"看到这句报错就点这个"的对照表 + 界面截图）。
> ▶ 界面已按**场景**分成五个页签：🚑 急救 / 🩺 诊断 / 🧩 插件与皮肤 / 🛡 配置保险箱 / 🔧 环境与维护。

---

## 一、这是什么

一个 **Windows 桌面救援工具**，专治 DSH 的这几类毛病：

| 症状 | 救星的对应能力 |
|---|---|
| DSH 网页打不开 / 白屏 / 一直是 401 | 抓认证地址、发现真实端口、一键拉起 |
| 启动要等半分钟以上 | 找出拖慢冷启动的元凶（如缺 pyyaml）并修 |
| 每隔一会儿弹一个 PowerShell 黑窗 | 定位四个来源（补丁缺失 / 默认终端被接管 / 轮询）并修 |
| 界面错乱、皮肤冲突 | 修复皮肤互斥登记 |
| 装完插件后出了毛病（起不来/调不了 API/功能失效） | 🩺 **装后体检** → 按它开头的对照表点 |
| 某个插件一装就崩 | 排查崩溃插件 → 一键禁用 |
| 配置文件被写坏、DSH 起不来 | **配置保险箱**：改动前快照 + 写后校验 + 自动回滚 |
| 想反馈问题但说不清 | **导出脱敏诊断包**，一个目录打包发出去 |

★ **它不联网、不上传任何东西**。全部操作都在你本机完成，诊断包导出前会自动脱敏（用户名与路径会替换成 `USER` / `~`）。

## 二、运行要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（64 位） |
| 前提 | **你的机器上已经装过 DSH**（DeepSeek Harness），且用过 `web` profile |
| 浏览器 | Microsoft Edge 或 Google Chrome（"打开无痕"需要） |
| 其他 | **都不需要**。不用装 Python、不用装 Node、不用管理员权限 |

**不需要安装**：解压到任意目录，双击 `大肥鱼救星.exe` 即可。
**不需要卸载**：删掉整个文件夹就行（它只在 `%USERPROFILE%\.dsh\big-fat-fish-rescuer\` 留有日志与配置快照 —— 想彻底清干净，把这个目录也删掉）。

> ⚠️ **首次运行可能被 Windows SmartScreen 拦**（因为是无签名程序）：
> 点「更多信息」→「仍要运行」。杀毒软件误报同理，加白名单即可。

## ★ v5.0 新增（2026-09-20）

> 这一版主要多了两样：一个**专治「插件装不上」的新按钮**，和一批**给爱折腾的人用的命令行开关**。
> 版本号只有两个出口：程序标题栏，以及 `--selftest` 输出的第一行。

### 装插件被拦下、说需要构建授权，怎么办？

先看日志里报的是不是这一句：

```
ERR_PNPM_IGNORED_BUILDS
```

它的意思是：**这个插件要跑自己的构建脚本，而宿主要求先点名授权。**
这不是插件坏了，是差一道授权手续 —— 去 `🧩 插件与皮肤` 页 → 分组「新插件适配（装插件被拦时点它）」→ 点 `🔍 研究插件`。

**它怎么工作**（你只管看它打印什么）：

1. 你输入插件包名，它先去 npm 查这个包的**最新版本**；
2. 在一个**临时目录**里干装一次 —— **绝对不碰你的 profile**；
3. 让 pnpm 自己报出「需要授权的包有哪些」；
4. 打印一份**预演**给你看：
   适用类别 / 前置条件 / 预演内容 / **★ 将改哪里**（哪个文件、加哪几行）/ 等价命令 / 复验判据 / 回滚方式。

**你点确认之后它才真动手**：

```
先备份 pnpm-workspace.yaml 与 pnpm-lock.yaml
  → 写入 allowBuilds 段
  → 在真实 profile 里跑一次 pnpm install 复验
  → 不通过就自动回滚（配置还原 + 再跑一次 install 把 node_modules 也还原）
```

> **真实例子**：查 `dsh-better-sidebar`，它会告诉你需要授权的是 `node-pty`。
>
> ★ 它**不猜**「哪个包要授权」—— 只认 pnpm 自己报出来的名单（猜的迟早会错）。

#### 安全边界（这段请一定看）

| 它**不会**做的事 | 它**会**做的事 |
|---|---|
| 结束正在运行的 DSH | 在你的真实 profile 里跑一次 `pnpm install` |
| 重启正在运行的 DSH | 所以插件目录会按新配置**重装一次** |

- 和 `🛡 只诊断` 的关系：**只诊断开着时，这个动作会被直接拒绝，一个字节都不写。**
- 想只看它打算做什么、先不动手：命令行 `--scout <包名>`（只预演）；要真动手再加 `--apply`。

### 命令行这批新开关（给爱折腾的人）

| 开关 | 一句话 |
|---|---|
| `--scout <包名>` | 研究插件，只预演不写入；加 `--apply` 才真动手 |
| `--scout-selftest` | 自检「我对真实 profile 到底动不动手」：13 项判据，全在临时沙箱 + 假 pnpm 里跑，不联网、不碰真实 profile |
| `--headless` | 无头只读体检：不弹窗，出一份**可转发**的报告；退出码 0/1 可给脚本用 |
| `--smart` | 一键智能启动并打开；加 `--dry` 只说它打算做什么、不动手 |
| `--readonly` | 安全总闸（同界面上的 `🛡 只诊断`），三种取值：on / off / status |
| `--plan-kill` | 预演：列出「现在动手会结束哪些进程」，**一个都不杀** |
| `--plan-fix all` | 把所有修复动作的六件套列出来（共 **8 个动作**） |
| `--corpus-check` | 拿真实语料库回归故障分类器 |
| `--classify <日志文件>` | 把任意一份 DSH 日志归类（属于哪一类故障、该点哪个按钮） |

**这几条要说清**：

- `--headless` 的报告写在 `%USERPROFILE%\.dsh\big-fat-fish-rescuer\headless-report.txt`；
  `--classify-only` 是纯函数模式（同一份日志在任何机器上结论一致）。
- `--smart`：端口上有健康的 dsh 就只打开不重启；有卡死的 dsh 残留就**只清掉确认是 dsh 的那些**；
  没人占就直接起；**被别的程序占着就换一个空闲端口，绝不杀别人的程序**。
- `--readonly on` 开了之后**绝不结束、绝不启动任何 dsh 进程** ——
  停止 / 重启 / 一键修复 / 强力自愈 / 插件适配都会被拒绝。
- `--plan-kill`：被**非 dsh 程序**占着的端口永远不在名单里。
- `--plan-fix all` 列的六件套＝前置条件 / 预演内容 / 将改哪里 / 等价命令 / 复验判据 / 回滚方式；
  `--fix-apply <动作id>` 才真执行（写前快照 → 执行 → 复验，复验不过自动回滚）。
- `--corpus-check`：**362 条语料 / 14 类**；当前精确率 94.0%、召回率 21.5%。
  门槛写死在程序里，判据退化会直接 exit 1。

## 四、按症状找按钮（推荐这样用）

### 场景 A：DSH 打不开 / 白屏 / 一直转

```
① 🔍 运行诊断        ← 先看它说什么
② ❓ 为何打不开      ← 按它的结论行动
③ 🩺 一键修复        ← 让工具自己按结论修
④ 🚀 启动并打开      ← 修完拉起界面
```
仍不行 → 点 `⚡ 强力自愈`（它会杀进程→释放端口→重启，**当前对话会断**）。

> 💡 **小知识**：DSH 的认证是**一次性 token**。不带 token 访问 `/` 永远是 401 ——
> 所以「能不能打开」不能靠"根地址返回 200"判断，救星会去抓带 token 的认证地址。

### 场景 B：能打开，但每次都要等很久

```
① 🚦 启动链路自检    ← 四项体检：端口 / 图标配置 / 认证地址 / 冷启动元凶
② 🧩 补丁体检        ← 看三个补丁还在不在（DSH 一升级就会被覆盖！）
③ 🔔 弹窗体检        ← 10 秒采样，看是谁在新建控制台窗口
```
最常见原因：**系统 python 缺 pyyaml**（会让 argo 检索后端每次冷启动反复退回默认配置）。
`🚦 启动链路自检` 会直接告诉你缺不缺。

### 场景 C：一直弹 PowerShell 黑窗

```
① 🔔 弹窗体检        ← 10 秒采样，直接抓出"是谁在弹"
② 🧩 补丁体检        ← 三个补丁缺哪个补哪个
③ 🖥 默认终端        ← 检查/修复"默认终端被 Windows Terminal 接管"
```
★ 这是历史上排查最久的一个问题，**四个来源**分别是：
① 工具自身的轮询（已改原生 API，不再弹）② DSH 缺 `CREATE_NO_WINDOW`
③ 检索插件缺 `windowsHide` + pyyaml 缺失 ④ **系统默认终端被设成 Windows Terminal**
⇒ 所以第 ④ 项只有 `🖥 默认终端` 能查到。

### 场景 D：界面错乱 / 皮肤冲突 / 插件装了就崩

```
🧩 插件兼容性        ← 逐一核对已装插件的产物与版本
🚨 排查崩溃插件      ← 扫日志找崩溃/不兼容的插件
⛔ 禁用崩溃插件      ← 把它写进 disabled（可恢复）
🩹 修复插件          ← 定位冲突插件并修复登记
💊 修复皮肤互斥      ← 原子写入 profile + home 两层互斥 patch（会先备份）
```

### 场景 E：配置被改坏 / DSH 起不来

```
🛡 备份配置          ← 手动打一个快照（改动前建议先点）
✅ 配置自检          ← 关键配置文件的合法性体检（JSON/YAML 结构）
📚 快照列表          ← 看历次快照
♻ 恢复配置          ← 从快照恢复（有确认框）
```

### 场景 F：日常维护

```
🔄 刷新状态          ← 更新顶部状态显示
📄 打开日志          ← 打开 dsh 输出日志并显示尾部
📋 导出报告          ← 完整诊断报告（文本）
📦 导出诊断包        ← 脱敏打包（要发给别人帮你排查时用这个）
```

## 六、命令行用法（可选，给爱折腾的人）

> ★ 两条最常用的：
> `.\大肥鱼救星.exe --classify "<日志文件>"` —— 把任意一份 DSH 报错日志**归类**（属于哪一类、
> 涉及哪个插件/包、该点哪个按钮），报告落在 `%USERPROFILE%\.dsh\big-fat-fish-rescuer\classify-report.txt`；
> `.\大肥鱼救星.exe --start` —— 命令行启动 dsh web 并**等它真的能响应**（起不来会直接说原因）。
> 另外：包内 `给别的AI用的_DSH排障指令.md` 是给任何模型用的排障指令；

## 九、端口：为什么有人是 3080、有人是 3081

**先给结论：DSH 默认 3080，但「3081」不是故障，是同一套机制的正常结果。**

端口的三个来源（任一不同，你看到的端口就不同）：

| 来源 | 说明 |
|---|---|
| DSH 自己 | 不指定时用 **3080** |
| 可靠启动器（`~/.dsh/tools/open-dsh.mjs`） | **从 3080 开始找第一个空闲端口** —— 3080 被残留 node 或别的程序占着，就会用 3081、3082… |
| 桌面图标的 `launcher.ini` | 里面写死的 `--port`（老版本里它和 Url 还可能不一致 ⇒ "点图标永远打不开"） |

**本工具怎么适配（v4.4 起）** —— 它不靠"端口号猜"，而是尽量靠**进程身份认**：

1. **有显式设置就先听你的**：环境变量 `DSH_PORT`，或文件
   `%USERPROFILE%\.dsh\big-fat-fish-rescuer\port.txt`（**只写端口号一行**，支持 `#` 注释）
2. **认正在运行的实例**：看这个监听端口背后的进程，命令行是不是真的指向 dsh 入口 ——
   **端口落在 3080-3179 之外也能认出来**（v4.4 新增）
3. 参考可靠启动器写的 `last-url.txt`、启动日志里的认证地址
4. **没在跑时**：以你桌面图标 `launcher.ini` 里的 `--port` 为准（免得图标认 3081、工具却起在 3080）
5. 都没有 → 回到默认 3080

**我该做什么？** 通常**什么都不用做**。只有这两种情况需要手动指定：

- 你的 DSH 跑在少见端口（如 1024 以下、3179 以上），**而且当前没在运行**（工具无法从进程身份上认出它）；
- 你希望工具与桌面图标统一固定到某个端口。

做法（任选一种，改完重启一次本工具即可）：

```powershell
# 方法一：环境变量（只对本次会话有效）
set DSH_PORT=3081

# 方法二：写文件（长期有效）
# 新建 %USERPROFILE%\.dsh\big-fat-fish-rescuer\port.txt，内容只写一行：3081
```

**怎么确认它认对了端口？** 三个地方都能看到：

- 界面最下方状态栏直接显示它正在用的地址（`http://127.0.0.1:<端口>/`）；
- `--selftest` 的报告里有一行：`端口发现：当前用 X（来源：…）`；
- `--diagnose` 导出的诊断包里同样有这一行（还带"显式设置"状态）。

> 如果那一行写着 **来源：身份扫描（★ 端口 X 在默认区间之外…）**，
> 说明它是**按进程身份**认出你的 DSH 的 —— 这正是"别人用 3081、你也不用改任何设置"的那条路。

## 中文用户名会不会出问题？（体检按钮：🈶 中文路径体检）

结论分两栏，别混：

**安全的**：DSH 本体。它把非 ASCII 路径转义成 ASCII 目录名——实测本机 `~/.dsh/sessions` 下是
`--C-Users-~6D4B~8BD5~7528~6237-Desktop-~9879~76EE--`，每个非 ASCII 字符写成 `~码点十六进制`
（6D4B=测、8BD5=试、7528=用、6237=户、9879=项、76EE=目）。救星会**把转义反解回来给你看**，
反解成功即证明这套机制可逆、读写不会错位。

**要防的**：外面那些小工具（都是本机实测踩过的）——
- Windows 上 Python 的输出流默认是 GBK（实测：文件系统 UTF-8、STDIO=GBK）⇒ 中文乱码，个别脚本直接 UnicodeEncodeError；建议设用户环境变量 `PYTHONUTF8=1`。
- mediapipe 传中文路径必败（报文件不存在、其实存在）⇒ 要用 `model_asset_buffer`。
- PowerShell 5.1 读**无 BOM 的 UTF-8 脚本**会按 GBK 解码 ⇒ 含中文的 .ps1 语法崩；含中文就存 UTF-8 with BOM。
- `.cmd`/批处理受 OEM 代码页影响，中文参数与回显可能乱码。

## 强力自愈能修什么？（按钮：📋 自愈能修什么）

**它不是「什么都救得回来」的按钮**，而是「把服务重新拉起来」的按钮。

**能治**：dsh 进程僵尸/卡死（含端口被上一次的 dsh 占着）、服务没起或起了但 HTTP 不应答、桌面启动器与 ComfyUI 缺件。

**治不了（会告诉你该点哪个按钮）**：插件树加载失败（重复 loader entry id / 悬空引用 / 入口缺失 / pending 服务）、配置写坏、**DSH 包本身缺失或被升级装坏**、端口被**别的程序**占着（它故意不误杀）、密钥缺失或模型名不存在、磁盘满/权限/杀软、网络与代理、中文路径引发的第三方工具失败、以及电脑本体（Windows 起不来、硬件坏）。

两个安全设计：动手前自动给配置拍快照；释放端口时**只结束确认是 dsh 的进程**，不会顺手杀别的软件。
另外它会**先看现在的状态**：服务活着就直接告诉你「现在用不上自愈」，不会吓唬你。

命令行同款：`--pathaudit`、`--selfheal-boundary`。
### 补：目录选择器陷阱（社区已核到源码行，2026-09-17 补）

有人确实被「中文名文件夹」坑过：DSH 官方讨论 #4648「当项目文件夹名称同时包含英文和中文时，DSH 无法选择其作为工作区」
（社区已核到源码行、给了补丁，并统计为同族第约 10 份报告，跟进见 #4624 / #4654）。

但**真正的规则不是「中文不行」**：名字里含 **UTF-16 低字节为 0x00 的字符**（码点末两位是 `00`，如「一」U+4E00、「开」U+5F00）时，
Windows 原生目录选择器只用每个码元的低字节判断字符串结束 ⇒ 路径在那个字之前被截断 ⇒ realpath 报 ENOENT ⇒ 工作区加不上。
所以「软件开发」会被截成「软件」，而**不含这类字的纯中文目录名完全正常**——这就是它看起来"有时候行有时候不行"的原因。

救星的「🈶 中文路径体检」会逐个字符查**你这台机器**上的路径，把中招的字和它所在的位置直接列出来。
判定方法：字符的码点**低字节为 0x00**（即 `(c & 0xFF) == 0`）就会中招；常见例子：「一」U+4E00、「开」U+5F00、「刀」U+5200。

真踩上时的三个绕法：①改名避开这类字；②**直接粘贴完整路径**，别用那个弹出选择框（手工输入不经过它）；③先挪到纯 ASCII 路径确认能加上，以此反证。

## 皮肤「鲸鱼娘 · 深海」（默认外观）

**这套皮肤是我（大肥鱼）自己做的**：底、字、按钮、页签、边框、头上的蝴蝶结与海浪，都是我自己定的、自己画的。

### 长什么样

- **暗色深海**底色（不吃纯黑，用深海蓝黑），卡片是深一档的面色 + 1px 描边 ⇒ 界面有层次，不糊成一片。
- **头部**：深海渐变 + 斜向光柱 + 两条海浪线 + 金色海平线，正中一枚**蝴蝶结**；
  左边立绘（主人的「女仆抱大药丸」）、右边鲸鱼（主人给的那张），两张图的**白底按"从四边泛洪"的方式抠掉**
  （只抠背景，药丸的白色上半截、女仆的白围裙原样保留）。
- **按钮**：按语义上色（绿=启动/修复、红=停止/关闭、橙=重启、青=主操作），字色自动选深浅保证看得清。
- **页签**：自绘暗色页签，选中态多一条青色下划线（不靠颜色单独表意）。
- **边框**：Win11 原生边框染成金色 + 里面一条金色细线（原生的贴边吸附/缩放/圆角都还在）。

### 为什么这么配（不是拍脑袋，有规矩）

配色按界面皮肤的通行做法来：**1 主色 + 1 强调色 + 3~5 中性色、彩色不超过 5 个、60-30-10 配比**
（底色 60% / 面色 30% / 点睛 10%）；**正文对比度 ≥4.5:1、描边等 UI 元素 ≥3:1**，
并且**用公式算过、写进了自检**（跑 `--selftest` 能看到每个配对的实测比值，比如正文 13.16:1、主按钮 10.67:1）。
暗色不用纯黑、文字不用纯白、彩色降饱和——都是同一套规矩里的条目。
